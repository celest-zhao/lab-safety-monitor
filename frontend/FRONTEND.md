# 前端说明 · Web 监控页与微信小程序

> 同一个实验室环境监测系统，两个前端：一个浏览器里看的单文件网页，一个微信里用的小程序。
> 数据来自同一套硬件（STM32 + 边缘 AI），但**走的链路完全不同**，改代码前先看第一节那张对照表。

## 一、两端对照

| | **Web 监控页** | **微信小程序** |
|---|---|---|
| 形态 | 单文件 HTML + 原生 JS + Chart.js | 原生小程序（WXML / WXSS / JS） |
| 入口 | `http://127.0.0.1:8000`（本机） | 微信中打开（体验版 / 正式版） |
| 位置 | `sensor_platform/public/index.html` | `iot-mp/miniprogram/` |
| 数据源 | 本地 `server.py` 的 `/api/*`，落 MySQL / SQLite | 云函数 `iotApi` → 华为云 IoTDA；`aiApi` → 阿里云百炼 |
| 刷新 | 2 秒轮询 4 个接口 | 30 秒定时（页面可见时才跑）+ 下拉刷新 |
| 鉴权 | 无（只在本机监听） | openid 白名单，未授权只能看空态 |
| 主题 | 深色单套 | 跟随系统 / 浅色 / 深色 三档 |
| 图表 | Chart.js（CDN） | 手写 canvas，无第三方依赖 |
| 能否离线 | 后端不在就没数据 | 云函数不可用时显示"本地答复" |

**为什么差这么多**：Web 页是给实验室现场大屏/电脑看的，直连本机后端，图省事要的是信息密度；小程序是给人在手机上随时随地看的，没有固定 IP 可用，只能靠云开发转发，所以要考虑鉴权、节流、流量费。

## 二、Web 监控页

### 2.1 页面结构

单页五段，自上而下按数据新鲜度排：**状态栏 → 10 张指标卡 → 4 张趋势图 → 20 条明细表**。深色主题、12 px 圆角卡片，趋势图桌面端 2×2 排布、窄屏单列。

- **状态栏**：连接状态、最近更新时间、数据库类型（mysql / sqlite）、记录总数，每 2 秒刷新
- **指标卡**：温度、湿度、光照、人体、Gas、融合分、融合等级、风扇、补光、AI 相似度
- **趋势图**：温度、湿度、光照强度、融合风险分，各一条线、单轴
- **明细表**：最近 20 条已落库记录，时间倒序，11 列

### 2.2 异常高亮

| 图表 | 判定 | 颜色 |
|---|---|---|
| 温度 | > 40 ℃ 或 < 0 ℃ | 玫红 |
| 湿度 | > 80% 或 < 20% | 玫红 |
| 光照强度 | < 100 lx（低光） | 琥珀 |
| 融合风险分 | > 75 严重 / > 50 关注 | 玫红 / 琥珀（常态紫） |

### 2.3 技术要点

- 单文件，无构建、无 npm，改完刷新浏览器即可
- **不能双击打开**：页面里的请求是相对路径 `/api/...`，`file://` 协议下必然 404，必须通过 `server.py` 托管
- 每 2 秒并发请求 `/api/readings?limit=80`、`/api/latest`、`/api/summary`、`/api/status`
- 取数用 `Promise.all`，任一接口失败只降级对应区块，不整页白屏

### 2.4 依赖的接口

| 接口 | 用途 |
|---|---|
| `POST /api/ingest` | 串口桥推一帧读数，只更新内存，落库按 20 秒节流 |
| `GET /api/readings?limit=N` | 最近 N 条历史（默认 200，上限 2000） |
| `GET /api/latest` | 最新一条（内存实时值，冷启动回退查库） |
| `GET /api/summary` | 记录总数 |
| `GET /api/status` | 数据库类型 |

### 2.5 跑起来

```bash
pip install pyserial pymysql
# 确认 MySQL 在跑（库表不存在会自动建；连不上自动回退 SQLite 的 sensor.db）
python run.py          # 单进程内同时起 server.py 和 serial_bridge.py
# 浏览器打开 http://127.0.0.1:8000
```

串口默认 `COM6 @ 115200`，接的是 STM32 的 USART2（经 CH340）。换机器先改这个。

## 三、微信小程序

### 3.1 页面矩阵

| 页面 | 路径 | 作用 |
|---|---|---|
| **设备**（首页） | `pages/device` | 自定义看板：6 项核心指标 + 用户自建模块 + 补光/风扇开关 + 报警摘要 + 桌宠 |
| **趋势** | `pages/trend` | 4 条曲线（温度/湿度/光强/AI 评分）+ 异常汇总卡 |
| 详情 | `pages/detail` | 单设备全量 13 项属性、上报时间、在线状态 |
| **报警** | `pages/alarm` | 列表、已读/未读、左滑删除、按级别清空 |
| **我的** | `pages/mine` | 账号与授权状态、主题切换、自检、关于 |

底部 4 个 tab 就是设备/趋势/报警/我的，详情页从设备页点进去。

首页的模块可自定义（新建、删除、恢复默认），配置只存在**手机本地** `wx.setStorageSync('dash_modules_v1')`，不写数据库、不调接口，所以换手机不同步。

### 3.2 数据链路

```
IoTDA 设备影子（13 项属性，5 秒一报）
   ↓  云函数 iotApi（AK/SK 只在服务端）
   ↓  overview / detail / trend / alarms / control
小程序页面  ←—— 30 秒自动刷新，force 跳过云端 30 秒节流

设备快照 snapshot
   ↓  云函数 aiApi（批量调百炼 deepseek-v4.1-flash）
   ↓  brief / chat / ask / health
桌宠 Luster 气泡
```

**前端不直连数据库、不直连 IoTDA，小程序包里没有任何密钥。** 所有读写都经 `wx.cloud.callFunction`，AK/SK 与大模型 key 只存在云函数的环境变量 / `config.js` 里。

### 3.3 `utils` 各管什么

| 文件 | 职责 |
|---|---|
| `api.js` | 云函数调用封装。统一把 `{ok:false}` 和平台错误码（-501000 函数没部署、INVALID_ENV 环境 ID 错）翻成人话 |
| `model.js` | 13 个属性的展示元数据（名称/单位/小数位）+ 阈值常量 + 格式化 |
| `dashboard.js` | 首页模块配置的增删改查，本地存储 |
| `l1.js` | L1 异常判定，算"最近一次越线的时间点"（趋势页异常汇总用） |
| `auto.js` | 页面自动刷新：onShow 启动、onHide 停止，上一轮没回来就跳过 |
| `theme.js` | 三档主题切换，管页面 class + 导航栏/tabBar 原生色 |
| `buddy-geo.js` | 桌宠的行走轨迹、落脚点碰撞 |
| `luster-brief.js` | 桌面简报文案拼装（本地兜底，不联网也能说话） |
| `luster-chat.js` | 对话降级文案、错误分类（`errTag`）、预设问答 |
| `luster-gesture.js` | 拖拽、点击、长按等手势响应 |
| `luster-lines.js` | 台词库，按时间段/状态挑句子 |

### 3.4 主题

官方 `darkmode` + `theme.json` 只能"跟随系统"，**没有手动切换的 API**（不存在 `wx.setTheme`），所以三档切换是自己接管的：

1. 页面 `data` 里写 `theme: theme.resolve()`（模块加载时算好，首屏不闪）
2. 根节点 class 加 `theme-{{theme}}`，CSS 变量随类切换
3. `onShow` 里调 `theme.apply(this)`，补齐导航栏和 tabBar 的原生颜色

深色主题叫"深空玻璃"：深底 + 半透明面板 + 细描边，浅色是同一套结构的反相。改配色只改 `app.wxss` 里的变量，别在页面里写死颜色。

### 3.5 桌宠 Luster

`components/ai-buddy`，一个组件包住气泡 + 动画 + 输入框。

- **说话**：`brief` 拿一段云端总结；云端不通就用 `luster-brief.js` 的本地文案，气泡角标写"本地答复"
- **追问**：`ask` 带最近 6 轮 `history`，云端会重新清洗（只认 user/assistant 角色、单条截 200 字），防止被塞进 system 角色绕过提示词
- **预设问题**：`chat` 传 `qid`（worst / temp / todo / alarm），不走自由输入
- **能不能打字**：由云端 `freeChat` 决定，端上不自己判断；`health` 返回 `freeChatWhy`（`ok` / `mode-off` / `no-open-id` / `not-in-list`）用于自检
- **动画**：canvas 逐帧画，按"空闲/说话/睡觉/走动"四态切帧，`buddy-geo.js` 管走动路径



### 3.6 阈值口径（重点）

两端的阈值**不是同一套**，因为看的指标不一样，不要互相抄：

| 指标 | Web 页 | 小程序 |
|---|---|---|
| 温度 | > 40 ℃ 或 < 0 ℃ | **≥ 35 ℃** |
| 湿度 | > 80% 或 < 20% | **≥ 80%** |
| 光照 | < 100 lx（偏暗） | **≥ 800**（过亮，单位未定标） |
| 综合 | 融合风险分 > 75 严重 / > 50 关注 | **AI 评分 < 20** 异常 |

小程序这边特别注意：**AI 评分是减分制**——100 分才正常，分数越低越偏离，所以判定方向是"小于"。写成"大于 70"就会变成"越健康越报警"）。

- `< 20` → 异常（L1）
- `20 ~ 50` → 偏离，注意
- `≥ 50` → 正常

设备偶尔上报 `255`，那是无效读数（不是满分），前端一律显示"读数无效"并排除出异常统计。

### 3.7 刷新与节流

| 层 | 周期 | 说明 |
|---|---|---|
| 设备上报 | 5 秒 | STM32 → IoTDA |
| 云函数拉 IoTDA | 30 秒 | `sync.staleSeconds`，页面带 `force` 可绕过 |
| 小程序刷新 | 30 秒 | 只在页面可见时跑，后台不空转 |
| Web 落库 | 20 秒 | 取窗口内最严重的一帧，避免高峰被采样跳过 |

调这个要成对改：页面刷新比云端节流快，用户就会看到"点了没反应"。

### 3.8 目录

```
miniprogram/
├── app.js / app.json / app.wxss / theme.json
├── pages/
│   ├── device/    首页看板（6 核心指标 + 自定义模块 + 控制）
│   ├── trend/     曲线 + 异常汇总
│   ├── detail/    单设备全量属性
│   ├── alarm/     报警列表
│   └── mine/      设置/自检/主题

│   └── ai-buddy/  桌宠（气泡 + 动画 + 输入）

```

## 四、两端要一起改的东西

1. **属性名**：`SHT30_T`、`SHT30_H`、`Light`、`Gas`、`Body_IR`、`Sound`、`Fill`、`Fan`、`AI_Score`、`Temp_Rise`、`Fuse_Level`、`Fuse_Score`、`Dominant`，共 13 个，直接对应 IoTDA 物模型，**改名就断**。
2. **阈值**：小程序的 `utils/model.js` 和云函数的 `cloudfunctions/iotApi/model.js` 里各有一份 `THRESHOLD`，是刻意的重复（云函数和小程序不能共享源码目录）。改一处必须同步另一处，否则前端显示"正常"、云端判"报警"。
3. **报警级别**：`severe / warning / info` 三档，前后端字符串必须一致。

## 五、本地开发速查

**Web**
```bash
python run.py     # 起后端 + 串口桥，浏览器开 127.0.0.1:8000
```
页面改了直接刷新；没数据先看串口有没有输出、MySQL 有没有起来（会自动回退 SQLite）。

**小程序**
1. 微信开发者工具打开 `iot-mp/`（**是这一层，不是里面的 `miniprogram/`**——`project.config.json` 里已指定 `miniprogramRoot`）
2. 右键 `cloudfunctions/iotApi` 和 `aiApi` → 上传并部署：**云端安装依赖**
3. 点右上角「上传」出体验版，再去 `mp.weixin.qq.com` → 版本管理 → 选为体验版
4. 手机上要看到新版：先删掉旧的小程序再进，否则读到缓存

改了 `miniprogram/` 只需重传小程序；改了 `cloudfunctions/` 必须重传对应云函数，两者不联动。
